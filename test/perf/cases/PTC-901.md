# PTC-901 — MOCK-901 throughput, trivial handler, journaling OFF

**Requirement.** MOCK-901 (901.1): sustain **≥20 000 `tools/call` rps** for 60 s,
trivial handler (`echo`), **journaling disabled**, with **p99 < 25 ms**, error
rate < 0.1%.

**Target environment.** `localhost` on this workstation only (authorized in the
TASK-029 brief). Apple M1 Max, darwin/arm64, 10 cores, 32 GiB. Loopback HTTP/1.1
plaintext, keep-alive on. **This is NOT the 4 vCPU Linux target the requirement
specifies** — every number is labelled *measured on this host* and any
comparison to the target is *extrapolated* with stated assumptions.

**Tool + why.** `k6` (v1.7.1). Reason: it is the installed, brief-preferred
generator; `constant-arrival-rate` gives an **open-model** offered rate, which is
mandatory for a latency-under-load measurement (a closed VU model would let the
server slow the offered rate and hide degradation). yandex-tank is not installed.

**Load model.** Open model, `constant-arrival-rate`. Offered rate is fixed
independent of server latency, so coordinated omission on the *offered rate* is
avoided; k6 still records per-request latency from send to receive.

**Load profile.**
- Warm-up: 30 s at target rate — **discarded** from all reported percentiles.
- Steady state: 60 s at 20 000 rps.
- Ramp (saturation search): stepped 10k → 20k → 40k → 80k → 120k rps, 20 s/step,
  to locate the knee and the achieved-rate divergence.

**Data characteristics.** Single canonical `tools/call` for built-in `echo` with
a small arguments object `{"msg":"..."}` and a complete `_meta` envelope
(protocolVersion + clientCapabilities + clientInfo) so it passes any
`validateMeta` mode. ~260-byte request, ~230-byte response. Keep-alive reused
connections (preAllocatedVUs sized so the generator is not connection-starved).

**Autostop / abort conditions (MANDATORY).** k6 thresholds with
`abortOnFail`: `http_req_failed rate < 0.01` and `http_req_duration p(99) <
250ms` (a generous abort ceiling — the *verdict* ceiling is the spec's 25 ms,
evaluated in analysis, not relaxed). A run that trips these aborts and is
reported as such.

**Monitored metrics.** Server side: process CPU% and RSS sampled at 1 Hz
(`ps`), GOMAXPROCS recorded. Generator side: k6 process CPU% sampled at 1 Hz to
prove headroom. k6: full-resolution JSON output for raw-data percentiles and
achieved-rate charts.

**Pass criteria (verdict).** PASS iff achieved rate ≥ 20 000 rps sustained 60 s
AND p99 < 25 ms AND error rate < 0.1% AND the generator was provably unsaturated.
Otherwise FAIL or INDETERMINATE-ON-THIS-HOST (with reason). Reported at both
GOMAXPROCS=4 (closest to the 4-vCPU core count) and GOMAXPROCS=10 (host native).

**Runs.** ≥3 per configuration; report spread.

**Expected duration.** ~3 min/steady run × 3 + ramp ≈ 20 min per GOMAXPROCS.
