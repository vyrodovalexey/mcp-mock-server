# Wire Annex

## 0. Status and epistemic position

`requirements.md` is the **sole normative source** for the `2026-07-28` semantics described here.
I could not confirm that this revision, its error codes, `server/discover`, `resultType`, MRTR /
`InputRequiredResult`, or `subscriptions/listen` correspond to any publicly published MCP
specification. **No claim is made either way** — the repository simply does not contain the
specification text, and nothing in this annex should be read as a statement about what MCP does or
does not define.

What follows is therefore split into:

| Label | Meaning | Count |
|---|---|---|
| `[R]` | Restated from `requirements.md`, with the section cited. | — |
| `[D]` | Derived — logically forced by an `[R]` item or by JSON-RPC 2.0 / RFC 9728 / W3C Trace Context. | — |
| `[P]` | **Proposed** — invented here to fill a gap an implementer cannot proceed without. **Requires ratification.** | **38** |

Every `[P]` item is listed in `gap-analysis.md` under GAP-003 with a recommended resolution.
This document is the input to `internal/wire`, to `test/mcpclient` (ADR-017), to the golden
fixtures, and to the self-check schema.

**Design accommodation (ADR-019):** all wire shapes are data, not code. Ratification changes this
file and `wire-2026-07-28.schema.json`; it does not change handler logic.

### Machine-checkable companion  (AMEND-4)

`wire-2026-07-28.schema.json` now **exists** alongside this prose, covering the **Phase 1 subset
only** — the `_meta` envelope, `server/discover`, `tools/list`, `tools/call`, the JSON-RPC envelope
and the `-32602` `data.missing` payload. It is versioned `v0` / `v1alpha1` and carries the
provisional warning in-band, in an `x-WARNING` array that any reader or tool encounters before the
schema body.

It exists so `MOCK-201.4` (`switches.selfCheck`) has something to validate against, and so golden
fixtures and `test/mcpclient` assert against an artifact rather than against prose. **Validating
against it proves self-consistency with this annex and nothing about interoperability.**

Phase 2+ surface — mirrored headers, `-32020/21/22`, pagination, SSE framing, MRTR, subscriptions,
legacy eras — is deliberately **absent** from the schema rather than present-and-permissive, so
that an accidental Phase 2 emission in Phase 1 fails the self-check loudly.

Two `[P]` items in the tool-result surface (`[P-39]`…`[P-52]`) are defined in
`contracts/builtin-tools.md` and registered there, continuing this annex's `[P-nn]` numbering.

## 3. Mirrored headers

`MOCK-204` requires validation of `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` and
`Mcp-Param-*` against the body, with `-32020` / `400` on mismatch, "including Base64-sentinel
decoding and numeric comparison of integers".

| # | Item | Label |
|---|---|---|
| 3.1 | `MCP-Protocol-Version` ≡ `_meta.protocolVersion`, exact string. | `[R]` |
| 3.2 | `Mcp-Method` ≡ JSON-RPC `method`, exact string. | `[R]` |
| 3.3 | `Mcp-Name` ≡ the primitive name in `params` (`params.name` for tools/prompts, `params.uri` for resources). | `[R]` + `[P-12]` for which field per method. |
| 3.4 | **Base64 sentinel format.** | `[P-13]` — **proposed: `=?B?<base64url-nopad-of-utf8>?=`**, chosen because it is unambiguous, is not valid as a bare header token, and echoes RFC 2047's encoded-word shape. A literal name that itself matches `^=\?B\?.*\?=$` MUST be encoded (`MOCK-223.6`). **This is the single most consequential `[P]` in the annex** — the hub's encoder must agree byte for byte. |
| 3.5 | Sentinel is REQUIRED when the name contains any byte outside `%x21-7E` excluding `:`, or exceeds the header-safe length. | `[P-14]` |
| 3.6 | `Mcp-Param-<Name>` mirrors `params.<name>`; `<Name>` is the param name in HTTP-header casing. | `[P-15]` — proposed: original param name, dot-free, with `_` mapped to `-`. |
| 3.7 | Integer comparison is **numeric**: `Mcp-Param-Limit: 007` matches `{"limit": 7}`. | `[R]` |
| 3.8 | Boolean comparison is by the keywords `true`/`false`, case-insensitive. | `[P-16]` |
| 3.9 | Float, array and object params are **not** mirrored. | `[P-17]` |
| 3.10 | A type mismatch (header `"7"` vs body `"7"` string) — whether `Mcp-Param-*` distinguishes string `"7"` from number `7`. | `[P-18]` — **proposed: yes, distinguishes.** The header alone is ambiguous, so the comparison mode is selected by the *body's* JSON type. |
| 3.11 | Header present, body field absent ⇒ mismatch; body field present, header absent ⇒ mismatch. | `[P-19]` — proposed both are mismatches; `MOCK-204.6` requires both be distinguishable. |
| 3.12 | Duplicate header occurrences ⇒ mismatch. | `[P-20]` |
| 3.13 | Header comparison is case-insensitive for the *name*, case-sensitive for the *value*. | `[D — RFC 9110]` |

## 9. Legacy eras — see `wire-legacy-2025.md`

`MOCK-301`…`306` describe `2025-11-25` (primary legacy), `2025-06-18`, `2025-03-26`. The legacy
annex covers: `initialize` / `notifications/initialized`, `Mcp-Session-Id` issuance and
validation, `DELETE` termination, `GET` SSE, `Last-Event-ID` replay, `ping`, `logging/setLevel`,
`resources/subscribe`/`unsubscribe`, server-initiated requests, and `-32002`.

**Era detection for `era: dual` (`MOCK-303`) — `[P]`, proposed:**

```
if method == "initialize" or method == "notifications/initialized"  -> legacy
else if MCP-Protocol-Version header present and in modern set       -> modern
else if params._meta.protocolVersion present and in modern set      -> modern
else if Mcp-Session-Id header present and matches a live session    -> legacy
else                                                                 -> configured `dualDefault` (default: modern)
```

This must be **total** (every input resolves) and deterministic. GAP-019.

## 10. What ratification changes

| If ratification changes… | Blast radius |
|---|---|
| `_meta` location (P-06) | Every request path; the independent client; all golden fixtures. **Largest.** |
| Sentinel format (P-13) | `MOCK-204`, `MOCK-223`, `assert.AssertHeaderMatchesBody`. Encoder/decoder pair + goldens. |
| `resultType` values (P-21) | One table in `internal/wire`; all goldens. |
| MRTR retry echo (P-37) | `internal/mrtr` digest computation; `MOCK-243` cross-request semantics. |
| HTTP status pairings (P-31/32) | One table; functional tests. |
| Capability shape (P-08) | `MOCK-206`, `MOCK-245`, `AssertCapabilitiesNotWidened`. |
| Everything else | A table entry and its goldens. |

This is why ADR-019 insists on no wire literals in handlers.
